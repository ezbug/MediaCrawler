# 企业邮件工作流五门

用于 POLYV 或 ZigoAI 企业推广邮件。嵌入现有多 Skill 的采集、写稿、发送步骤，
按用户当前邮件任务执行，无须另建审核服务、审核角色或定时任务。

## 现有角色接力

- 采集与证据员：从公司官网、官方公告或可信公开披露渠道读取活动，记录公司、
  事件名称、事件发生日期、原文和来源 URL。同公司同事件去重。未来活动钩子只使用
  当前起未来60天内的事件；公告发布日期、半年报发布日期不能替代活动日期。
- 资格分析与文案员：把证据填进对应公司的邮件，按邮箱公开标记的职能选择称呼和话题，
  使用已核实的产品资料与同行案例。内部判断与邮件正文分开。
- 现有核验员与主代理：核对最终正文、收件人和五门结果；主代理复用当前已授权的
  Gmail/Ego Lite 发送路径。文案或收件人变动后重新判断。

网页操作复用 Ego Lite/Jev。无需为每封邮件或每个门创建新的浏览器空间。
活动证据、来源链接和门结果保存在邮件账本，证据链接不写进对外邮件。

## 五门

1. **真实钩子**：公司、事件名和活动日期在来源原文中对应一致。找不到证据就标记缺证据；
   不把搜索摘要或旧模板当作证明。不用“贵司”掩盖未确认的公司归属。
2. **公司与事件匹配**：活动确实属于收件公司，集团与子公司需要写明对应关系；
   禁止套用其他公司的日期或活动成果。
3. **业务相关**：明确解释事件与企业直播、私域直播、视频点播、企业培训、视频安全、
   SDK选型，或 ZigoAI 销售执行场景的关联。分红、纯股东表决等不构成关联。
   投资者交流活动可以匹配远程互动/回放，但不据此推断经销商培训问题。
4. **职能对口**：称呼和邮件话题匹配该邮箱的公开角色或来源说明。
   培训口谈培训，IR口谈投资者交流，市场口谈发布会/展会。
   邮箱前缀只是辅助线索；官网明确角色优先。仅SMTP接受不能证明职能或最终送达。
5. **成稿完整**：最终正文没有测试标记、模板变量、内部审核句或“发送前确认”等措辞。
   “免费开通测试账号”是正常产品文案，不属于测试标记。

逐封保存：`company / to / hook / event_date / source_url / source_quote /
recipient_role / gate_results / blocked_reasons / final_text`。
任一门未通过，保留具体原因并交用户确认，不自行豁免；补证或修改后仍须重新判断。
通过五门且已有明确发送授权的邮件直接推进，不重复索要已给过的授权。

## 发送与卡片同步

沿用现行模板与客户案例 RAG；称呼按收件职能调整，署名和地址遵守用户约定。
当前对外邮件不含电话或网页链接，使用已验证的 A-100 列表预览处理。
发送前核对实际收件人、主题与实填正文。发送后记录 Gmail 的发送证据，
把“已发送”“退信”“最终送达”分开表述；发送结果同步 Obsidian 对应公司卡片。
失效邮箱从可用邮箱 frontmatter 移除，退信原因保留在正文与台账。结果不明先回查，
不重复发送。

## 判断样例

- 某公司半年报8月28日发布，说明会10月16日召开：两个日期分别核对，
  不据半年报日期断言说明会已结束。说明会钩子给培训邮箱且正文谈培训，职能门不通过。
- 套用另一公司日期：公司事件门不通过。
- 正文残留测试标记或模板变量：成稿门不通过。
- 用分红公告推广培训：业务门不通过。
- 真实新品发布活动，市场职能明确，邮件讨论远程参加与回放：满足五门可推进。

当前批次数、公司清单、具体活动与发送进度只放活动账本，不写入永久规则。
