# 机构公开需求漏斗

机构公开需求与社媒公开回复是两个独立漏斗，不能互相补数。

## 机构漏斗

`官方公告/采购需求 -> 主体与原文核验 -> URL校验 -> 项目状态 -> POLYV匹配 -> P0/P1/P2/待核 -> 销售跟进表`

计入“可核验机构需求”必须具备：

- 明确机构主体；
- 机构官网或官方采购渠道原文，或有可核验的官方旁证；
- 可重新打开的来源链接；
- 需求原文和真实发布日期/时间状态；
- 项目状态（进行中、已截止、已成交、单一来源或待核）；
- 与课程直播、企业培训平台、活动线上传播、视频平台或内容保护相关的匹配理由。

单一来源、已成交和已截止项目可以保留为需求证据，但不得标记为开放商机。转载页面、采购人不明、官方原文失效且没有旁证的记录进入“待核”。

优先级：

- `P0`：截止时间未过且项目仍在进行；
- `P1`：近期截止，需核中标、成交或采购进度；
- `P2`：历史需求、已成交、单一来源或续约观察；
- `待核`：主体、URL、日期、项目范围或状态缺失。

## 社媒漏斗

`业务事件搜索 -> 评论来源核验 -> 买方原话 -> 身份核验 -> 评分 -> 定位 -> Dry-Run -> 明确授权发送 -> 发布后回查`

搜索卡片、正文、推荐内容、分享按钮文本和视频作者宣传不能冒充评论。只有确认文本来自真实评论容器后，才能统计评论渠道的资格率或得出“渠道不匹配”结论。

机构需求不计入社媒100条；机构线索也不自动触发评论、私信、点赞或关注。

## Grok 到 Codex 同步

Grok 只写自己的活动账本和 `grok-to-codex-latest.{json,md}`。Codex 通过 `takeover-sync` 重算计数和源文件哈希，并生成 `codex-takeover-latest.{json,md}`。临时批次数量和具体机构不写入永久 Skill。
